# EDQSG-U1.2 建设性修订与实现报告

## 1. 修订背景

U1.1已经解决“删除物理外键后DQ6失去检测入口”的问题，但SG3仍把物理外键可信率作为固定组成部分，可能误罚因高并发、批量加载、分布式边界或历史系统原因未建立物理外键、但具备成熟替代控制的生产数据库。

U1.2将评价对象从“外键是否存在”升级为“预期关系是否明确、完整性控制是否充分、控制运行是否有效”。

## 2. 模型调整

- SG3由“键与约束完整性”细化为“基础键约束+预期关系完整性控制”；
- SG4重点评价关系语义、责任、基数、删除更新策略和受控例外；
- DQ6以预期关系清单为检测入口，无论是否存在物理外键均执行孤儿检测；
- 底线从“关键关系缺少物理外键”改为“关键关系控制有效度不足或实际孤儿率超限”；
- 根因和治理任务统一使用“关系完整性控制不足”，避免把特定技术实现误当作治理目标。

## 3. 代码调整

- `sqlserver/config.py`：新增`RelationshipControlRule`，支持替代控制、控制证据、受控例外、阈值与重要度；
- `sqlserver/profiler.py`：自动匹配物理外键，计算机制强度、控制有效度、语义完整度、例外治理分和孤儿率；
- `sqlserver/analyzer.py`：重构DQ6、SG3、SG4和底线逻辑；
- `sqlserver/pipeline.py`：报告预期关系数量、无可信物理外键关系数量和受控例外数量；
- 保留`logical_foreign_keys`兼容路径，但标记为旧版简化配置。

## 4. 数据库与验证数据调整

AeroMRO新增：

- `dq.relationship_control_registry`：保存预期关系和控制真值；
- 三份关系控制配置：物理外键基线、受控无外键、非受控无外键；
- 两个结构场景：`SG3_controlled_no_physical_fk.sql`和`SG3_uncontrolled_no_physical_fk.sql`；
- 一个阴性对照负载：`W_SG3_controlled_relation_valid_workload.sql`；
- 一组传播负载：非受控场景产生孤儿记录并验证SG3→DQ6；
- `relationship_control_experiments.csv`：记录实验条件和预期结果。

## 5. 测试结果

执行：

```bash
python -m pytest -q
```

结果：**32项测试全部通过**。新增测试覆盖：

- 关系控制配置解析与校验；
- 无物理外键但替代控制充分时不自动误罚；
- 无物理外键且控制不足时触发底线；
- 可信物理外键被识别为强控制；
- AeroMRO受控/非受控场景与真值矩阵完整性。

当前环境未连接真实SQL Server，数据库端DDL兼容性、执行计划和大规模负载仍需在SQL Server 2019及以上实例验证。
